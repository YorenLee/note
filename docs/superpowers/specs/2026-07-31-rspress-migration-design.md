# Rspress 知识库迁移设计

## 目标

将当前以 Obsidian 目录组织的 Markdown 知识库迁移为标准 Rspress 文档站。迁移后以 Rspress 为唯一维护入口，不再保留 Obsidian 兼容要求。

完成后的仓库应当能够：

- 使用包管理器安装依赖并启动本地开发服务器。
- 生成可部署的静态站点。
- 按「前端、后端、LLM、职场实践、运维、书单」展示现有内容。
- 支持中文导航、多级侧边栏、全文搜索、代码高亮和页面目录。
- 正常加载现有本地图片，并保留外部图片与外部链接。

## 项目结构

采用 Rspress 推荐的 `docs/` 内容目录：

```text
.
├── docs/
│   ├── index.md
│   ├── 01前端/
│   ├── 02后端/
│   ├── 03LLM/
│   ├── 04职场实践/
│   ├── 05运维/
│   └── 06书单/
├── package.json
├── pnpm-lock.yaml
├── rspress.config.ts
└── README.md
```

现有分类目录及其 `assets/` 子目录整体移动到 `docs/`。同目录相对图片引用保持不变。仓库根目录的旧 `index.md` 转换为站点首页，原 `README.md` 改为项目开发说明。

设计文档保存在 `docs/superpowers/specs/`，但通过 Rspress 配置从用户侧导航和侧边栏中隐藏，避免混入知识库正文。

## 站点信息架构

顶部导航提供首页及六个一级分类入口。每个分类使用自动生成的侧边栏，目录层级与当前文件夹层级一致。

首页使用 Rspress 首页布局，包括：

- 知识库名称与一句话介绍。
- 进入笔记的主操作按钮。
- 六个分类的功能卡片。
- 简洁的技术文档视觉风格。

文档页面使用 Rspress 默认主题能力，开启本地全文搜索、标题锚点、右侧大纲、代码复制和代码高亮。主题仅做轻量品牌色与首页样式定制，不引入独立 React 业务组件。

## 内容迁移规则

- Markdown 正文原则上不重写，只处理阻止 Rspress 构建或渲染的兼容性问题。
- 保留已有 frontmatter；缺少标题时，由文件名或首个标题生成显示名称。
- 保留中文、空格及现有目录层级；仅在路由或构建工具无法处理时做最小重命名。
- 保留标准 Markdown 图片和链接。
- Obsidian 专有语法按出现情况转换：
  - Callout 转换为 Rspress 支持的提示容器。
  - `==高亮==` 转换为 HTML `<mark>` 或等价 Markdown 扩展。
  - Wiki 链接若存在，则转换为标准相对链接。
- 空文件仍可保留，但需要补充最小标题，避免生成无意义页面。
- `.obsidian/` 不进入站点内容，并加入忽略策略。

## 配置与开发体验

使用 pnpm 管理依赖，并提供以下脚本：

- `pnpm dev`：启动 Rspress 开发服务器。
- `pnpm build`：生成生产静态站点。
- `pnpm preview`：预览生产构建。

`rspress.config.ts` 负责站点标题、描述、导航、侧边栏、搜索、主题设置、图标以及构建排除项。导航和侧边栏优先使用目录自动生成能力，避免新增笔记时重复维护大量配置。

`.gitignore` 忽略依赖、Rspress 缓存和构建产物。README 记录安装、开发、构建和新增文章的方法。

## 错误处理

迁移脚本或批量移动前先确认工作区状态，保留用户现有的 `.obsidian/workspace.json` 未提交修改。文件移动使用 Git 可识别的方式完成，避免内容丢失。

生产构建是主要兼容性检查。若构建报告无效 frontmatter、MDX 解析、死链接或资源路径错误，则只修复对应文档，不对无关内容做格式化。

## 验证

迁移完成后执行：

1. 安装依赖并生成锁文件。
2. 运行 `pnpm build`，要求退出码为 0。
3. 检查生成目录包含首页及六个一级分类页面。
4. 检查代表性页面：含本地图片的 Docker/Linux、深层目录的 webpack/LangChain、长文档和代码块。
5. 启动站点并进行一次浏览器视觉检查，确认首页、导航、侧边栏、搜索入口和图片显示正常。
6. 检查 Git 状态，确保 `.obsidian/workspace.json` 未被误提交或覆盖。

## 非目标

- 不在本次迁移中重写或补全笔记正文。
- 不接入评论、登录、数据库或服务端 API。
- 不配置具体托管平台和自动部署流水线。
- 不实现重型自定义主题或独立组件库。
