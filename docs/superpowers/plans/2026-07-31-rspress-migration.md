# Rspress Knowledge Base Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert the existing Markdown knowledge repository into a buildable, Chinese-language Rspress documentation site without rewriting note content.

**Architecture:** Move all six content categories beneath Rspress's `docs/` root and let Rspress v2 generate navigation from `_nav.json` and sidebars from per-directory `_meta.json`. Keep framework configuration, theme CSS, and package metadata at repository root; validate compatibility by building the complete static site.

**Tech Stack:** Node.js 20.19+ or 22.12+, pnpm, Rspress v2 (`@rspress/core`), TypeScript configuration, Markdown/MDX, CSS.

## Global Constraints

- Rspress becomes the only supported authoring/build workflow; Obsidian compatibility is not required.
- Preserve the six top-level categories: 前端、后端、LLM、职场实践、运维、书单.
- Preserve note bodies and local asset-relative paths unless a concrete Rspress build error requires a focused compatibility fix.
- Do not overwrite or commit the user's existing `.obsidian/workspace.json` modification.
- Do not add deployment workflows, authentication, comments, databases, APIs, or a heavy custom React theme.
- Production verification requires `pnpm build` to exit with code 0.

---

## File Map

- `package.json`: package identity, package manager, Node engine, and Rspress scripts.
- `pnpm-lock.yaml`: exact dependency resolution generated by pnpm.
- `tsconfig.json`: TypeScript environment required by the Rspress config.
- `rspress.config.ts`: content root, Chinese locale, site metadata, global CSS, route exclusions, and theme behavior.
- `styles/index.css`: restrained brand colors and homepage polish using default-theme variables/classes.
- `.gitignore`: dependency, cache, and `doc_build` exclusions.
- `README.md`: contributor-facing install, development, build, preview, and article-authoring instructions.
- `docs/index.md`: Rspress homepage.
- `docs/_nav.json`: generated top navigation order and Chinese labels.
- `docs/<category>/_meta.json`: per-category sidebar order/labels.
- `docs/01前端` through `docs/06书单`: migrated notes and colocated assets.
- `docs/superpowers`: internal design and implementation records, excluded from routes.

### Task 3: Fix Markdown compatibility and validate representative content

**Files:**
- Modify only: Markdown files named by actual `pnpm build` errors.
- Modify only if present: files containing Obsidian callouts, highlights, or wiki links.

**Interfaces:**
- Consumes: the full site configuration from Task 2.
- Produces: a zero-error production build with functional local resources.

- [ ] **Step 1: Inventory incompatible syntax**

Run:

```bash
grep -RIn --include='*.md' -E '^> \[![a-zA-Z-]+\]|==[^=]+==|\[\[[^]]+\]\]' docs/01前端 docs/02后端 docs/03LLM docs/04职场实践 docs/05运维 docs/06书单
find docs -name '*.md' -size 0 -print
```

Expected: an exact file/line inventory. Do not alter matches inside fenced code examples.

- [ ] **Step 2: Apply focused conversions**

For prose-only matches:

- Convert `> [!warning] 标题` blocks to `:::warning[标题] ... :::`.
- Convert `> [!info] 标题` blocks to `:::info[标题] ... :::`.
- Convert `==文字==` to `<mark>文字</mark>`.
- Convert `[[relative/path|label]]` to `[label](relative/path)` and `[[relative/path]]` to `[relative/path](relative/path)`.
- Add `# <filename without numeric prefix>` to each zero-byte page.

Use `apply_patch` for each affected file and leave unrelated whitespace/content untouched.

- [ ] **Step 3: Run the complete build and fix reported files iteratively**

Run: `pnpm build`

Expected: exit 0. For any failure, capture the named file and line, make the smallest compatibility correction, and rerun the complete command until it exits 0.
